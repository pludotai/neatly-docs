---
title: "Credentials"
description: "Manage Skyvern portal credentials and optional email TOTP routing"
---

The Credentials page stores a local record for a Skyvern password credential. The web app sends the username and password to Skyvern when creating or updating the credential, then stores the returned Skyvern credential ID and workspace metadata. The local password is not included in credential summaries.

## Credential fields

| Field | Use |
| --- | --- |
| Name | Human-readable label shown in selectors |
| Link | Optional portal URL or reference shown to operators |
| Username | Portal login username |
| Password | Sent to Skyvern on create or update; never returned in the credential summary |
| Enable email TOTP | Adds Skyvern `totp_type: email` configuration |
| Sender email | Stored as the Skyvern TOTP identifier when TOTP is enabled |

The password input may be blank in the current server contract; a blank value is replaced with the Skyvern placeholder `passwordless`. Treat edits as secret updates and provide the real password whenever the portal credential must change.

## Use credentials in a workflow

A Skyvern workflow declares a parameter with type `credential_id`. The appointment form lists credentials that have a Skyvern ID and submits that ID. If the workflow also declares a matching string parameter ending in `_user_id` or `_username`, the form supplies the credential username alongside the credential ID.

This pairing supports workflows that need both a secure password reference and a visible username input without exposing the password to the web application after storage.

## TOTP relationship

When email TOTP is enabled, the local record includes a `totpIdentifier`. Skyvern uses that identifier to associate an incoming verification message with the waiting workflow. Configure an OTP delivery path as described in [OTP](/features/otp).

<Warning>
  Credential names and portal links are operator metadata. Treat usernames, passwords, Skyvern credential IDs, TOTP identifiers, database backups, and logs as sensitive. Do not place secrets in workflow parameter JSON or documentation examples.
</Warning>
