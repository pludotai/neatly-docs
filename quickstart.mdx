This quickstart starts the web application with PostgreSQL. Skyvern, S3-compatible storage, and OTP delivery are optional for the UI boot, but required for the corresponding runtime features.

## Prerequisites

- Bun compatible with the repository toolchain
- Docker and Docker Compose
- PostgreSQL, supplied by the repository's Compose file
- A Skyvern API key for workflow execution
- A session secret for signed cookies
- S3-compatible credentials if workflows download files

## Start PostgreSQL

From the `web` repository:

```bash
docker compose up -d db
```

The included Compose file exposes PostgreSQL on `localhost:5432` with the development database `carrier_portal`. Change those development defaults before sharing the environment.

## Install and configure

```bash
bun install
cp .env.example .env
```

Set `DATABASE_URL`, `SKYVERN_API_KEY`, and `SESSION_SECRET`. Add the S3 variables described in [Configuration](/operations/configuration) when file downloads are needed.

Apply the schema and seed local users:

```bash
bun run db:migrate
bun run db:seed
```

The seed script creates development users. Replace the sample credentials before using a shared or production database.

## Run the web app

```bash
bun run dev
```

Open `http://localhost:3000`. Sign in, create a carrier as a super admin, attach one or more Skyvern workflow IDs, and create an appointment from the Appointments page.

## Run the email service

The email service is independent. From `email-service`:

```bash
go run ./cmd/server
```

Or run the included container setup:

```bash
docker compose up --build
```

Set its Microsoft Graph, API authentication, Skyvern, and optional OTP watcher variables before starting it. See [Email service](/services/email-service) and [Configuration](/operations/configuration).

<Warning>
  Do not copy seeded passwords, API keys, OAuth client secrets, database URLs, or OTP state files into source control. The sample seed values are development-only.
</Warning>
